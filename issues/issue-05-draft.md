# If I Could, Would You? Issue #5

## The Main Story: Bright Beginnings

This week I figured I should do the "vibe" coding walkthrough I've teased the previous two weeks, but it occurred to me that it's an awful big ask for an audience that might have no idea what vibe coding even is, let alone why anybody not already interested in programming would want to start.

So this week is about me diving headfirst into a domain I know nothing about publicly and seeing if the result is enough to get you excited about what kind of damage you can do in a domain you know deeply.

Because if you're not excited, you're not invited, people!

And I'm not gonna reach for something easy that I know will give us the success story we all want. You and I are gonna find out if I can make my wife a happy camper this week. So this could go spectacularly badly, but it is also the sort of project that I think a lot of people can relate to.

But anyway, the wife and her bestie have recently been working on starting up their own business getting little ones ready for pre-school.
And this week my wife has tasked me with this: (see attached)

[[IMAGE: her request screenshot, private details cropped]]

So full disclosure, I have no experience in creating YouTube videos, animating children's books, IP law, or how to go about any of this. I have no animating software, no editing tools, and frankly, very little patience for the type of detail work this really takes. I'm a big picture guy. If you asked me what color shirt I'm wearing, I have to look down.

And the really worrisome part of putting all my newsletter eggs in this one basket? I have only attempted to use AI to create a video one other time and it ended up using up 300 dollars in free cloud credits plus another 60 of my real money before I finally caught it. And the result of all that spending was 4 short videos that kinda worked as placeholders to show my idea, but left my 8 year old rolling her eyes because it was "so AI." It certainly wasn't a finished product. And I have no interest in setting the budget for this project anywhere above freemium.

So why try? Why does she even feel like she can ask me for something like this? Because time and time again, AI surprises us. If we're just stubborn enough and have our quota reset just enough times, we can pretty much figure out anything. That's my opinion at least.

So I started where I start almost every build these days, in chatgpt's chat interface because it's free and doesn't cut into my codex (the chat gpt that codes on your computer) usage. Claude chat does, so frankly, I haven't "chatted" with Claude outside my terminal (where Claude Code lives) in months and use my entire quota up on coding every week. (I think it's a silly business model because now Anthropic is missing out on all of my actual thinking while Open AI gets to keep training on it.)

But really, if we're going to build in public, we may as well give it the full I dunno wtf I'm doing experience with my bootleg mixture of experts using free AI chat apps.

You see, I found early on that when using AI to work in a space where I'm out of my depth, it helps to get a second opinion. And a 3rd and a 4th and just as many as you can because they're free. So this is where my research starts.

First, I ask for a file from one of my coding agents prepared with all of the relevant context about the business idea, the builds we've already done, the apps and code that could be reusable from my daughter's reading app, and anything else it could think of that I would need to use with my chats to think this through including the actual prompt.

If you don't have that luxury, just try to prepare all the information a real person going about this task might ask for, doesn't matter how messy, and dump it in. It's a lot like dropping all your disorganized receipts off with your tax guy and letting him figure out what's important and why.

Then, like I said, I start with one chat, I give it the file, my pretty ambiguous goal, and I have it start doing research, list its assumptions, ask me questions, and attempt to remove anything unclear. Basically interview me until we're feeling good about the specifications. Then I run the same prompt in other free chats. Not every AI can search every place so I find this is especially useful when looking for additional perspectives and sources and when trying to get constructive criticism.

Then I bring all those responses back to the main chat. I gotta be honest I don't even read any of them first. I ask the main chat to do its own fact checking on the additional information and we do the assumption and question dance each time as it keeps a running document with the whole plan and all the decisions we've made.

Each time we add more open source options, more research on products that can already do this, how they have changed, what we can glean from their own users. Additional data.

Still, I haven't really learned or invested anything, I'm just accumulating information. But once I feel like I have enough, I work through the problem as much as I can in the chat. I have it write some of the code if it can; to prepare everything it can to make my coding agent as efficient and effective as possible. I even have it write the prompt so all I need to do is copy and paste it with the file when I'm ready to hand off to a coding agent.

Then I do that little "I'm gonna get a second opinion, doc" trick again on the final version just to make sure we didn't go too far off the reservation. I let my main chat go through each critique for me, taking what's good, dropping what's off base, asking me about what's genuinely still up for interpretation.

Then, and only then, am I'm finally ready to start spending real resources. So I take my upgraded file and prompt and I dump it into my coding agent and I tell it to make it's own plan based off the actual environment with this plan as the starting off point. And at this point, I purposely took a hands off approach for most of the build so that you can put yourself in my shoes and see how easy this stuff is:

## Word of the Week: MVP

**MVP:** Minimum Viable Product

**Definition:** That version of a new product which allows a team to collect the maximum amount of validated learning about customers with the least effort.

[Eric Ries, Minimum Viable Product: A Guide (2009)](https://www.startuplessonslearned.com/2009/08/minimum-viable-product-guide.html)

**Used in a "sentence":**

> MVP success comes down to activation, cohort retention, and a defensible LTV:CAC ratio, measured over a fair time window and paired with direct user feedback.

**In Plain Ammer:** first shareable draft

**See also:** [don't be a homer](https://www.youtube.com/watch?v=WPc-VEqBPHI).

[Sentence source](https://letsbuildmyapp.com/blog/mvp-success-metrics)
